SUPPORTED MODERNIZATION PATH
Exact Expo SDK upgrade sequence
Treat the remaining SDK-managed high findings as an incremental mobile-platform upgrade, not a lockfile override exercise.
01
Baseline
Create a dedicated branch. Capture tests, type checks, and the production audit before change.
02
Refresh SDK 54
Take the latest supported patch in the current SDK line first.
expo install expo@^54.0.0 --fix
03
Align modules
Use Expo’s resolver for every Expo-owned module; do not manually pin native package versions.
expo install --fix
04
Diagnose
Resolve all SDK compatibility, peer, and configuration findings before native builds.
expo-doctor
05
Update native
Regenerate CNG projects or apply pod and native-project helper changes.
expo prebuild / pod-install
06
Prove builds
Run web, Android, iOS, development-build, and physical-device smoke tests.
07
Re-audit
Re-run production audit. If highs persist, move one SDK at a time to the next supported release.
Automated gate
Root and mobile tests, root and mobile TypeScript checks, package lock refresh, and production audit must all pass.
Native gate
Prove push, camera, storage, routing, theme, and offline flows on Android and iOS before releasing. Never force transitive Expo dependencies.
Source: Expo’s official upgrade walkthrough recommends incremental upgrades, expo install --fix, expo-doctor, and native-project regeneration or upgrade steps. [1]
